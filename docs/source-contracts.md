# Source contracts

Energy Compass binds sources through Home Assistant selectors and validates a preview before trusting a recommendation. The integration does not require any particular price, solar, battery, or load provider. Provider presets suggest visible mappings that users can change. Setup profiles pre-fill tuning only, never sources.

## Observed provider schemas

The following mappings were checked against the indicated integration source versions. Authentication to the Home Assistant state and recorder APIs was unavailable during this check, so no current entity state, attribute payload, or statistic metadata was verified. Setup must inspect the selected entities and statistics on each installation.

| Optional preset source | Source shape and meaning | Required normalization |
| --- | --- | --- |
| RCE PSE 2.0.1 price forecast | `prices` is a list of records. Each `rce_pln` is a signed raw market price in PLN/MWh; `dtime` is the **end** of a 15-minute interval. The source also exposes `last_update` and `data_points`. `dtime` may be a naive local timestamp, and the provider parser accepts an hour-24 notation. Tomorrow's records may be absent. | Subtract 15 minutes from each end time; divide by 1000 for PLN/kWh. Require the selected source timezone for naive times and reject ambiguous repeated local hours. Preserve negative prices. Do not use a clipped prosumer-price field as the raw price. Import and export settlement transforms remain independent user choices. |
| Solcast 4.6.1 detailed forecast | `detailedForecast` records use `period_start` and `pv_estimate`; the provider also defines `pv_estimate10` and `pv_estimate90`. Source code integrates `pv_estimate` as average kW over a 30-minute period. | Multiply each average kW value by 0.5 hour to obtain kWh for its interval. Validate timestamps, issue age, units, overlap, and gaps. Treat `detailedHourly` as a separate mapping until its exact aggregation is validated. A scalar daily solar total is insufficient for interval optimization. |

Further provider facts used by [Detected sources](guide.en.md#detected-sources-new-installations), read from the provider sources:

| Provider | Fact |
| --- | --- |
| `rce_pse` | The today and tomorrow sensors are `unknown` with an empty `prices` list before tomorrow's publication and after midnight. The option `price_unit` = `PLN/kWh` changes the sensors' unit and also scales the records (rounded to 0.01), so Energy Compass requires PLN/MWh. |
| ha-solarman (Deye profiles) | The inverter `Battery` sensor (translation key `battery`) is the inverter SOC in % and carries the BMS value as the attribute `BMS SOC`. Per-pack `Battery N` sensors (`battery_N`) belong to a separate BMS device of the same config entry and may be disabled with it. |
| Energy dashboard solar forecast (`wh_hours`) | Solcast: 30-minute period starts with Wh per period for the estimate chosen in the integration options, night omitted apart from one or two zero padding slots, up to 730 days of history and 14 days ahead. Open-Meteo: hourly period starts with Wh, zeros kept. Forecast.Solar: irregular keys with Wh; the dashboard reads each key as the start of its hour. Energy Compass sums Wh per local hour as the dashboard does. |

Source references: [RCE PSE](https://github.com/Lewa-Reka/ha-rce-pse), [Solcast](https://github.com/BJReplay/ha-solcast-solar). The checked installed versions were 2.0.1 and 4.6.1 respectively; future provider versions require schema revalidation.

## Generic selected inputs

Price and PV selectors must capture the entity, state or attribute, observed record paths, units, timestamp interpretation, source timezone where needed, and freshness limit. Today/tomorrow continuations merge by interval and must agree on overlaps. Separate PV arrays/sites can add only when explicitly grouped as additive. Negative import or export values remain valid input data.

Battery setup must bind an SOC source with percent, fraction, or energy interpretation and select capacity, hardware floor, operating floor, ceiling, and power limits. Optional independent BMS and throughput sources need their own unit and freshness checks. An unavailable or stale SOC, contradictory SOC sources, or unverified capacity must block a trusted battery recommendation. The current live SOC and capacity were not verified by API access.

Household load must come from a selected consumption energy statistic, a power source with sufficient history, a forecast, or an explicit fixed estimate. Grid import alone is not household consumption. Counter resets must not create negative consumption. No live load statistic, grid limit, or recorder retention was verified by API access; the setup preview must validate the selected data and keep missing inputs provisional.

## Pure source interfaces

The source layer imports no Home Assistant runtime modules. `SourceConfig` in `config_models.py` contains independent `PriceSource` values for buy and sell (mode `fixed`, `forecast` or, for buy in PLN only, `schedule` with a `TariffSchedule` from `sources/tariffs.py`; a forecast may carry `floor_per_kwh`, applied to the normalized value before the multiplier, VAT and addition; both keys are serialized only when set), `PvSource` with explicit additive arrays and continuation groups, a selected `LoadSource` mode, optional SOC/BMS bindings, numeric settings, and currency. `SourceConfig.to_dict()` / `from_dict()` serialize the mappings for config entries. `validate_sources(config, own_entity_ids)` checks enabled-component requirements and direct output feedback loops. Provider presets in `presets.py` contain only visible field suggestions, never live entity IDs.

`EntityBinding(entity_id, registry_id=None, attribute=None)` selects a state or attribute. `resolve_binding(states, binding)` reads a snapshot mapping keyed by entity ID, where each value has `state`, `attributes`, and `last_updated`. `rebind_entity(binding, registry_entities)` takes a mapping from stable registry ID to current entity ID; absence requires reconfiguration. Task 5 owns registry event handling. `field_paths(sample)` discovers scalar nested record paths; `field(record, path)` accepts only dot-separated keys, without indexing or evaluation. Bindings have `to_dict()` / `from_dict()` methods.

`IntervalBinding(entity, value_path, start_path/end_path, duration_path/interval_minutes, unit, unit_path, value_kind, value_sign, source_timezone, published_path, max_age_seconds)` maps either an array of interval records or a timestamp-keyed numeric map. `parse_intervals(states, binding, now)` returns UTC `Interval(start, end, value)` rows. Energy and average power both normalize to kWh; price normalizes to currency/kWh. An explicit offset wins; naive local timestamps require `source_timezone`. Ambiguous or nonexistent DST times, scalar forecast values, nonfinite values, stale publications, and invalid units raise `InputError`. For source age, `max_age_seconds` checks the selected entity's `last_updated`; `published_path` can additionally point into the state snapshot, for example `attributes.last_update`.

`price_for_slots(source, states, now, slots, currency, *, timezone=None, schedule_rates=None)` chooses fixed, forecast or schedule price (a schedule needs the installation `timezone` and the resolved `schedule_rates` for `peak` and `off_peak`, and reads no entity), resolves helper-backed multiplier and addition once, checks currency, and requires full settlement coverage. `price_series(...)` and `raw_rce_prices(...)` expose interval rows for previews. RCE is raw market input; import and export transforms are independently configured. `pv_series(states, binding, now, continuations=...)` deduplicates one array's continuations; `sum_pv_arrays(arrays, slots=...)` adds only arrays explicitly grouped as independent sources. `resample_energy`, `resample_power`, and `resample_prices` in `engine.normalize` cover requested intervals by exact overlap. A price slot spanning two different prices is invalid; the caller must retain tariff resolution.

`load_for_slots(source, states, now, slots, timezone, settings, statistics=(), power_samples=(), fallback_daily_kwh=None)` selects forecast, recorder, or explicit daily estimate. The HA coordinator must query recorder statistics in its executor and pass complete `start`/`sum` rows or timestamped power samples. `recorder_statistics_to_hours` uses recorder's reset-adjusted `sum`: each hourly row stores the last cumulative sum within that hour, so the difference between consecutive rows belongs to the second row's hour and becomes usable only after that hour ends; `counter_statistics_to_hours` skips reset crossings when only raw counters are available. `power_samples_to_hours` integrates observed power over complete hours. Native unknown/unavailable states remain timestamped `None` markers, including when an attribute is selected; an outage contributes no coverage, so affected hours are excluded without discarding other complete hours. The maximum sample gap still bounds numeric observations. `forecast_load(history, slots, timezone, fallback_daily_kwh, settings)` groups complete historical hours by local weekday/weekend and hour, with UTC interval identity. Incomplete, future, and out-of-lookback history cannot contribute. Missing buckets use daily-load/24 only when enabled and supplied.

`resolve_numeric(setting, states, now, max_age_seconds=...)` handles a fixed value or an entity-backed value (state or attribute), with declared input unit, multiplier, output unit, and range. Entity-backed `NumericSetting.max_age_seconds` is serialized and defaults to 86,400 seconds; an explicit `None` disables age checking for long-lived manual helpers. Age uses HA `last_updated`, while unavailable or unknown states always fail. Fixed values have no freshness check. Price resolution applies this limit to helper-backed multipliers and additions. The options UI must show the selected limit or the disabled choice. `LoadSource.power_max_gap_minutes` is serialized and defaults to 60 minutes; a longer gap raises `InputError` instead of inventing hourly load. `validate_soc(value, unit, measured_at, now, settings, previous=..., bms_kwh=...)` returns SOC in kWh or raises `InputError`; `SocTracker.accept(...)` retains the last trusted reading and requires a newer plausible reading after rejection. The coordinator owns state retrieval and must not treat an attribute as SOC until its unit and meaning have been selected and previewed.

The synthetic fixtures under `tests/fixtures/` exercise the observed price and PV record fields and generic Home Assistant state shapes. They contain no captured household values or identifiers.
